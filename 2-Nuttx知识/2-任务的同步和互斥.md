# 任务的同步和互斥1：信号量实现共享资源保护

## 概述

本示例演示了在 **PX4/Nuttx 实时操作系统**中，如何使用 **信号量（Semaphore）** 实现多个任务对**共享资源的互斥访问**。通过 `px4_task_spawn_cmd` 创建两个并发的子任务，它们同时对一个全局计数器 `cnt` 进行累加操作，信号量保证每次只有一个任务能进入临界区修改计数器。

## 代码结构

```cpp
#include <px4_platform_common/log.h>
#include <px4_platform_common/tasks.h>
#include <px4_platform_common/sem.h>

static px4_task_t task_id = -1;
static bool _task_should_exit = false;
static const unsigned int MAX_CNT = 100000;
static unsigned int cnt = 0;
static px4_sem_t sem;
```

## 核心实现

### 信号量初始化

```cpp
px4_sem_init(&sem, 0, 1);  // 0=线程间共享, 1=初始值（二元信号量）
```

### 子任务：临界区保护

```cpp
int run2(int argc, char *argv[])
{
    for (unsigned int i = 0; i < MAX_CNT; i++) {
        px4_sem_wait(&sem);   // P 操作：获取信号量
        // --- 临界区 ---
        unsigned int local_cnt = cnt;
        ++local_cnt;
        cnt = local_cnt;
        // --- 临界区结束 ---
        px4_sem_post(&sem);   // V 操作：释放信号量
        px4_sleep(0);          // 让出 CPU
    }
    return PX4_OK;
}
```

### 主任务：创建子任务并监控

```cpp
int run()
{
    px4_sem_init(&sem, 0, 1);
    px4_task_spawn_cmd("test_app2", SCHED_DEFAULT, PRIORITY_MIN + 10,
        1024, (px4_main_t)run2, nullptr);
    px4_task_spawn_cmd("test_app3", SCHED_DEFAULT, PRIORITY_MIN + 10,
        1024, (px4_main_t)run2, nullptr);

    while (!_task_should_exit) {
        if (!px4_task_is_running("test_app2") &&
            !px4_task_is_running("test_app3")) {
            PX4_INFO("cnt = %d", cnt);
        }
        px4_sleep(1);
    }
    px4_sem_destroy(&sem);
    return PX4_OK;
}
```

## 信号量工作原理

| 函数 | 操作 | 含义 |
|------|------|------|
| `px4_sem_init(&sem, 0, 1)` | 初始化 | 创建信号量，初始值=1 |
| `px4_sem_wait(&sem)` | P 操作 | sem>0 则 sem--；sem=0 则阻塞等待 |
| `px4_sem_post(&sem)` | V 操作 | sem++，若有等待者则唤醒 |
| `px4_sem_destroy(&sem)` | 销毁 | 释放信号量资源 |

> 初始值为 1 的二元信号量等价于互斥锁（Mutex），保证一次只有一个任务进入临界区。

## 为什么需要信号量？

无信号量时两个任务同时 `cnt++` 会发生**竞态条件（Race Condition）**：

```
test_app2: 读 cnt=100     test_app3: 读 cnt=100   ← 同时读到旧值
test_app2: 计算 101        test_app3: 计算 101
test_app2: 写回 cnt=101    test_app3: 写回 cnt=101
                    结果: cnt=101（丢失了一次更新！）
```

预期结果：两个任务各累加 100000 次，cnt 应为 **200000**。无信号量时会小于这个值。

## 关键知识点

| 概念 | 说明 |
|------|------|
| **临界区** | 访问共享资源的代码段，一次只允许一个任务进入 |
| **信号量** | P/V 操作实现互斥与同步 |
| **竞态条件** | 多任务并发访问共享数据，结果依赖执行时序 |
| **px4_task_spawn_cmd** | PX4/Nuttx 的任务创建 API |
| **px4_task_is_running** | 按任务名称查询任务是否仍在运行 |
