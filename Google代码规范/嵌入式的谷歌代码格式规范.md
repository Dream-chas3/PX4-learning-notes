# 嵌入式 Google 代码格式规范（基础实验阶段）

> 项目：四旋翼无人机飞控教学实验系统  
> 当前范围：STM32F103 基础实验  
> 编程语言：C  
> 外设驱动：STM32F10x 标准外设库（SPL）  
> 文档状态：第一阶段

## 1. 规范目的

本规范以 Google 代码风格的“可读、一致、易维护”为主要原则，结合
STM32F103、标准外设库、中断和外设驱动的特点，统一基础实验代码。

当前只覆盖以下实验：

1. 流水灯实验；
2. 蜂鸣器实验；
3. 按键及外部中断实验；
4. 定时器和计数器实验；
5. 串口通信实验；
6. I²C 与 DHT20 实验；
7. SPI 与液晶屏实验；
8. ADC 采集实验；
9. SD 卡实验。

姿态解算、PID、电机控制、飞行状态机等功能不属于当前阶段，不在本规范
中展开。

## 2. 适用原则

### 2.1 代码首先是给人看的

代码首先用于团队成员、教师和学生阅读，其次才由编译器执行。不能只以
“能够运行”作为代码合格标准，还必须做到容易理解、容易检查和容易修改。

- 使用能够表达意图的文件名、函数名和变量名；
- 代码结构应让首次阅读的人能够快速找到初始化、输入、处理和输出；
- 不为了少写几行代码而牺牲可读性；
- 不依赖只有原作者才知道的隐含规则；
- 一段代码如果需要反复解释，应优先改进代码结构和命名。

### 2.2 简洁直接，禁止炫技

优先选择最清晰、最直接并且容易验证的实现。禁止为了展示技巧而使用复杂
宏、晦涩表达式、过度封装或不必要的算法技巧。

- 简单的 `if`、`for` 和函数调用优于难懂的组合表达式；
- 禁止在一行中完成多个互不相关的操作；
- 禁止使用会产生隐藏副作用的宏；
- 不提前设计当前实验不需要的通用框架；
- 不为了“高级感”引入动态内存、复杂回调链或过度抽象；
- 只有在测量证明存在性能问题后才进行针对性优化；
- 优化后的代码如果不直观，必须说明原因、前提和测试结果。

推荐：

```c
if (KeyIsPressed(kKeyUser)) {
  LedToggle(kLedStatus);
}
```

不推荐：

```c
KeyIsPressed(kKeyUser) && (LedToggle(kLedStatus), true);
```

### 2.3 保持一致

同一项目中的命名、缩进、错误处理和接口形式应保持一致。个人偏好不能凌驾
于项目已经确定的规则。

- 新代码遵循本规范；
- 修改已有项目代码时优先保持模块内部一致；
- 相同类型的驱动采用相似的初始化、读写和错误返回方式；
- 不在同一模块中随意混用多种命名和排版风格；
- 自动格式化工具只负责排版，不能代替设计判断。

### 2.4 单一职责

一个文件负责一个模块，一个函数完成一个明确任务。初始化、读取、处理、
显示和错误处理应按职责拆分。

例如，`Dht20ReadSample()` 只负责读取和解析DHT20数据，不应同时刷新LCD、
发送串口消息和写入SD卡。这些动作应由实验应用层组织。

- 函数保持短小，通常不超过约50行；
- 嵌套层级通常不超过3层；
- 参数过多时应重新检查职责划分；
- 重复代码应提取成命名明确的函数；
- 不创建只为转调一次、没有增加含义的无效封装。

### 2.5 作用域最小化

数据和接口只在确实需要的范围内可见。

- 局部变量在接近首次使用的位置定义；
- 文件私有函数和变量使用 `static`；
- 头文件只暴露模块使用者需要的接口；
- 避免全局变量，跨模块状态通过函数接口访问；
- 输入参数不需要修改时使用 `const`；
- 硬件资源由对应BSP模块统一管理。

### 2.6 明确优于隐式

代码应明确表达数据含义、单位、边界、执行环境和失败方式。

- 时间、电压、温度和频率等名称应带单位；
- 函数返回值应明确表达成功、失败或错误类型；
- 所有数组、缓冲区和索引必须有边界；
- 所有外设轮询必须有超时；
- 中断与主循环共享的数据必须明确标记和保护；
- 硬件有效电平、总线模式和引脚分配不能依靠猜测。

### 2.7 注释解释原因

好的命名和结构用于说明“代码做什么”，注释主要说明“为什么这样做”。

- 注释硬件限制、协议时序和不直观的设计决定；
- 不逐行翻译显而易见的代码；
- 修改实现时同步更新注释；
- 临时方案应写明原因和后续处理条件；
- 不使用注释掩盖混乱代码，应先重构代码。

### 2.8 正确性优先于性能

基础实验首先保证功能正确、边界明确和行为可验证，再考虑速度和代码大小。

- 不进行未经测量的“猜测式优化”；
- 不为节省极少量代码空间而破坏模块结构；
- 优化不能绕过必要的错误检查和超时处理；
- 涉及中断、DMA和时序的优化必须经过硬件测试；
- 优化前后应保留可复现的测试条件。

### 2.9 当前项目执行要求

1. 项目代码遵循本规范，STM32标准库、CMSIS、FatFs等第三方代码保持
   原有格式。
2. 优先使用STM32F10x标准外设库，不使用HAL库。
3. 标准库没有提供合适功能时才能直接操作寄存器，并在代码中说明原因。
4. 外设底层操作集中在BSP驱动层，实验代码不得到处直接操作寄存器。
5. 所有实验必须具备明确的初始化入口和演示入口。
6. 中断函数只处理紧急、短小的工作，复杂处理放在主循环中完成。
7. 代码必须能够在启用常用编译警告后无新增警告地通过编译。

│  ├─ bsp_usart.c/.h
│  ├─ bsp_i2c.c/.h
│  ├─ bsp_dht20.c/.h
│  ├─ bsp_spi.c/.h

### 3.1 分层要求

- `Libraries`：只保存标准库和 CMSIS，不放项目业务代码。
- `Bsp`：封装 GPIO、TIM、USART、I²C、SPI、ADC 和 SD 卡等硬件操作。
- `App`：组织实验流程，只调用 BSP 公共接口。
- `Middleware`：保存 FatFs 等中间件。
- `Utils`：保存时间、错误处理等公共功能。

例如，流水灯实验应调用 `LedSet()`，不应在实验文件中直接调用
`GPIO_SetBits()`。

## 4. 文件规范

### 4.1 文件命名

文件名使用小写字母和下划线：

```text
bsp_sd_card.c
bsp_sd_card.h
experiment_key_exti.c
system_time.c
```

禁止使用含义不明确的文件名：

```text
test.c
new.c
temp1.c
功能.c
```

### 4.2 头文件保护

每个头文件都必须使用唯一的头文件保护：

```c
#ifndef BSP_BSP_LED_H_
#define BSP_BSP_LED_H_

#include <stdbool.h>
#include <stdint.h>

void LedInitialize(void);
void LedSet(uint8_t led_index, bool is_on);
void LedToggle(uint8_t led_index);

#endif  // BSP_BSP_LED_H_
```

### 4.3 头文件要求

- 头文件必须能够独立包含；
- 只声明模块使用者需要的接口；
- 禁止在头文件中定义普通全局变量；
- 私有函数和私有变量只放在 `.c` 文件中，并添加 `static`；
- 不允许依赖其他头文件的间接包含。

### 4.4 `#include` 顺序

按以下顺序排列，各组之间空一行：

1. 当前 `.c` 对应的头文件；
2. C 标准库头文件；
3. CMSIS、STM32 标准库和中间件头文件；
4. 项目其他头文件。

```c
#include "bsp_dht20.h"

#include <stdbool.h>
#include <stdint.h>

#include "stm32f10x.h"
#include "stm32f10x_i2c.h"

#include "app_error.h"
#include "system_time.h"
```

### 4.5 `.c` 文件内容顺序

一个源文件按以下顺序组织：

1. 对应头文件；
2. 其他头文件；
3. 文件内常量和宏；
4. 文件内类型；
5. 文件内静态变量；
6. 私有函数声明；
7. 公共函数定义；
8. 私有函数定义。

## 5. 排版规范

### 5.1 缩进

- 使用2个空格缩进；
- 禁止使用Tab；
- 行尾不得保留空格；
- 文件末尾保留一个换行。

### 5.2 行宽

每行原则上不超过80个字符。过长的函数调用应换行：

```c
const SdCardResult result = SdCardWrite(
    file_name, write_buffer, write_length, timeout_ms);
```

### 5.3 大括号

左大括号放在当前行末尾。即使只有一条语句，也必须写大括号：

```c
if (KeyIsPressed(kKeyUser)) {
  BuzzerSet(true);
}
```

禁止：

```c
if (KeyIsPressed(kKeyUser))
  BuzzerSet(true);
```

### 5.4 空格

二元运算符两侧留空格，逗号后留空格，函数名与左括号之间不留空格：

```c
adc_voltage_mv = adc_value * kReferenceVoltageMv / kAdcMaximumValue;
UsartSendData(USART1, transmit_data, data_length);
```

### 5.5 条件语句

- 布尔变量直接判断，不与 `true` 或 `false` 比较；
- 指针与 `NULL` 比较；
- 不在条件表达式中进行赋值；
- 复杂条件拆分成有意义的布尔变量。

```c
const bool card_ready = SdCardIsReady();
const bool data_valid = write_data != NULL && data_length > 0U;

if (card_ready && data_valid) {
  SdCardWriteData(write_data, data_length);
}
```

### 5.6 `switch` 语句

每个分支必须明确使用 `break`、`return`，或者写出贯穿注释：

```c
switch (experiment_id) {
  case kExperimentLed:
    ExperimentLedRun();
    break;

  case kExperimentBuzzer:
    ExperimentBuzzerRun();
    break;

  default:
    AppErrorReport(kAppErrorInvalidExperiment);
    break;
}
```

## 6. 命名规范

| 对象 | 命名方式 | 示例 |
|---|---|---|
| 文件 | 小写下划线 | `bsp_sd_card.c` |
| 结构体、枚举、类型 | 大驼峰 | `Dht20Sample` |
| 项目函数 | 大驼峰 | `Dht20ReadSample()` |
| 普通变量、参数 | 小写下划线 | `temperature_c` |
| 常量 | `k`加大驼峰 | `kUsartBaudRate` |
| 枚举值 | `k`加大驼峰 | `kKeyPressed` |
| 宏 | 全大写下划线 | `BSP_LED_COUNT` |
| 中断函数 | 芯片规定名称 | `USART1_IRQHandler()` |
| 标准库函数 | 保持官方名称 | `GPIO_SetBits()` |

### 6.1 类型

```c
typedef struct {
  float temperature_c;
  float humidity_percent;
  bool is_valid;
} Dht20Sample;

typedef enum {
  kSdCardResultOk = 0,
  kSdCardResultNotReady,
  kSdCardResultTimeout,
  kSdCardResultIoError,
} SdCardResult;
```

### 6.2 函数

项目函数采用“对象或模块 + 动作”的形式：

```c
void LedInitialize(void);
void BuzzerSet(bool is_on);
bool KeyIsPressed(uint8_t key_index);
void TimerInitialize(void);
bool UsartSendData(const uint8_t *data, uint16_t length);
bool Dht20ReadSample(Dht20Sample *sample);
void LcdDrawText(uint16_t x, uint16_t y, const char *text);
uint16_t AdcReadRaw(uint8_t channel);
SdCardResult SdCardMount(void);
```

标准外设库、中断入口和 FatFs 函数保持原始名称：

```c
GPIO_SetBits(GPIOA, GPIO_Pin_5);
TIM_SetCompare1(TIM3, compare_value);
SPI_I2S_SendData(SPI1, transmit_data);
void EXTI0_IRQHandler(void);
FRESULT file_result = f_mount(&file_system, "0:", 1U);
```

### 6.3 变量

变量名应说明含义，物理量和时间建议带单位：

```c
uint32_t elapsed_ms;
uint16_t adc_voltage_mv;
float temperature_c;
uint32_t spi_timeout_us;
```

禁止使用：

```c
int a;
int temp1;
float data;
uint32_t value;
```

### 6.4 常量与宏

```c
static const uint32_t kUsartBaudRate = 115200U;
static const uint32_t kDht20TimeoutMs = 100U;
static const uint16_t kAdcMaximumValue = 4095U;

#define BSP_LED_COUNT 4U
#define BSP_SD_CS_PIN GPIO_Pin_12
```

优先使用 `static const`、`enum` 和 `static inline` 函数。只在条件编译、
芯片引脚定义等必要场景使用宏。

### 6.5 标准库命名

不得为了符合项目命名规则而修改标准库接口：

```c
RCC_APB2PeriphClockCmd(...);
GPIO_Init(...);
USART_ITConfig(...);
I2C_GenerateSTART(...);
ADC_SoftwareStartConvCmd(...);
```

## 7. 数据类型

### 7.1 固定宽度整数

使用 `<stdint.h>` 中的固定宽度类型：

```c
uint8_t receive_byte;
int16_t adc_offset;
uint16_t lcd_color;
uint32_t system_tick_ms;
```

涉及寄存器、通信数据和存储数据时，不使用宽度不明确的 `long`。

### 7.2 布尔类型

开关状态使用 `<stdbool.h>` 中的 `bool`：

```c
bool is_led_on;
bool sd_card_ready;
bool usart_frame_received;
```

### 7.3 整数字面量

无符号常量添加 `U` 或 `UL` 后缀：

```c
uint16_t sample_count = 100U;
uint32_t baud_rate = 115200UL;
```

### 7.4 浮点数

STM32F103 没有硬件浮点单元，基础实验中只在确有需要时使用浮点数。
单精度常量添加 `f` 后缀：

```c
float temperature_c = 25.0f;
float reference_voltage_v = 3.3f;
```

ADC 原始值、毫伏值等适合使用整数的数据优先使用整数。

## 8. 标准外设库使用规范

### 8.1 工程配置

- 固定 STM32F10x 标准外设库版本，不混用不同版本文件；
- 在工程中定义 `USE_STDPERIPH_DRIVER`；
- 根据芯片容量定义正确宏，例如 `STM32F10X_MD`；
- `startup_stm32f10x_md.s` 等启动文件必须与芯片容量匹配；
- `stm32f10x_conf.h` 只包含当前工程需要的标准库头文件；
- 修改系统时钟后同步更新 `SystemCoreClock` 并检查各外设时钟。

### 8.2 外设初始化

每个BSP模块负责自己的时钟、GPIO和外设初始化：

```c
void LedInitialize(void) {
  GPIO_InitTypeDef gpio_init = {0};

  RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE);

  gpio_init.GPIO_Pin = GPIO_Pin_13;
  gpio_init.GPIO_Mode = GPIO_Mode_Out_PP;
  gpio_init.GPIO_Speed = GPIO_Speed_2MHz;
  GPIO_Init(GPIOC, &gpio_init);

  GPIO_SetBits(GPIOC, GPIO_Pin_13);
}
```

初始化函数重复调用时不应产生危险状态。重要输出应先设置为安全状态。

### 8.3 BSP封装

实验应用层只调用BSP接口：

```c
void ExperimentLedRun(void) {
  for (uint8_t led_index = 0U; led_index < BSP_LED_COUNT;
       ++led_index) {
    LedSet(led_index, true);
    DelayMs(kLedStepDelayMs);
    LedSet(led_index, false);
  }
}
```

不推荐在实验文件中直接散布以下代码：

```c
GPIO_ResetBits(GPIOC, GPIO_Pin_13);
```

### 8.4 状态与超时

标准库很多函数没有返回值，因此必须通过状态标志和有限超时判断结果。
禁止无退出条件地等待外设状态：

```c
bool UsartWaitForTransmitComplete(uint32_t timeout_ms) {
  const uint32_t start_ms = SystemTimeGetMs();

  while (USART_GetFlagStatus(USART1, USART_FLAG_TC) == RESET) {
    if ((SystemTimeGetMs() - start_ms) >= timeout_ms) {
      return false;
    }
  }

  return true;
}
```

禁止：

```c
while (USART_GetFlagStatus(USART1, USART_FLAG_TC) == RESET) {
}
```

## 9. 基础实验接口规范

### 9.1 流水灯

```c
void LedInitialize(void);
void LedSet(uint8_t led_index, bool is_on);
void LedToggle(uint8_t led_index);
```

- LED有效电平只在BSP内部处理；
- 应用层不关心LED是高电平点亮还是低电平点亮；
- LED索引必须检查范围。

### 9.2 蜂鸣器

```c
void BuzzerInitialize(void);
void BuzzerSet(bool is_on);
void BuzzerSetFrequency(uint32_t frequency_hz);
```

- 有源蜂鸣器使用GPIO开关；
- 无源蜂鸣器使用TIM PWM；
- 频率参数必须带 `_hz` 单位后缀。

### 9.3 按键与外部中断

```c
void KeyInitialize(void);
bool KeyIsPressed(uint8_t key_index);
bool KeyGetAndClearEvent(uint8_t key_index);
```

中断中只记录事件并清除标志：

```c
static volatile bool user_key_event_pending;

void EXTI0_IRQHandler(void) {
  if (EXTI_GetITStatus(EXTI_Line0) != RESET) {
    user_key_event_pending = true;
    EXTI_ClearITPendingBit(EXTI_Line0);
  }
}
```

按键消抖放在定时任务或主循环，不在中断中进行阻塞延时。

### 9.4 定时器与计数器

```c
void TimerInitialize(void);
uint32_t TimerGetCount(void);
void TimerResetCount(void);
```

- 注释写明定时器时钟、预分频、计数周期和中断频率；
- 中断函数名保持芯片规定形式；
- 中断入口必须检查并清除对应中断标志。

### 9.5 串口通信

```c
void UsartInitialize(uint32_t baud_rate);
bool UsartSendData(const uint8_t *data, uint16_t length);
bool UsartReadByte(uint8_t *data);
```

- 波特率变量使用 `_baud_rate` 或明确名称；
- 接收中断只读数据并写入环形缓冲区；
- 禁止在中断中执行阻塞式字符串打印；
- 缓冲区读写必须进行边界检查。

### 9.6 I²C与DHT20

```c
void I2cInitialize(void);
bool I2cWrite(uint8_t device_address,
              const uint8_t *data,
              uint16_t length,
              uint32_t timeout_ms);
bool Dht20ReadSample(Dht20Sample *sample);
```

- 统一规定设备地址使用7位地址还是左移后的8位地址；
- 建议项目接口使用7位地址，调用标准库时再转换；
- 检查BUSY、START、ADDR、TXE、RXNE等事件并设置超时；
- DHT20校验、状态位和测量等待由DHT20驱动处理。

### 9.7 SPI与液晶屏

```c
void SpiInitialize(void);
bool SpiTransfer(const uint8_t *transmit_data,
                 uint8_t *receive_data,
                 uint16_t length,
                 uint32_t timeout_us);
void LcdDrawText(uint16_t x, uint16_t y, const char *text);
```

- 在驱动中明确SPI模式、位序和最大时钟；
- 片选信号由具体设备驱动管理；
- LCD的命令、数据选择引脚只在LCD驱动中操作；
- 大量像素传输可使用DMA，但完成标志必须正确处理。

### 9.8 ADC采集

```c
void AdcInitialize(void);
uint16_t AdcReadRaw(uint8_t channel);
uint32_t AdcConvertToMillivolts(uint16_t raw_value);
```

- 注释说明ADC通道与实际引脚；
- 明确参考电压和量化位数；
- 原始ADC值使用整数；
- 多次采样和滤波函数与单次采样函数分开。

### 9.9 SD卡

```c
SdCardResult SdCardInitialize(void);
SdCardResult SdCardMount(void);
SdCardResult SdCardWriteText(const char *file_name, const char *text);
SdCardResult SdCardUnmount(void);
```

- 当前阶段使用SPI模式访问SD卡；
- 建议使用16GB或32GB microSDHC卡，并格式化为FAT32；
- 底层SPI、SD协议和FatFs分别封装；
- 检查 `f_mount()`、`f_open()`、`f_write()`、`f_sync()` 和 `f_close()`
  的返回值；
- 写入完成后正确关闭文件，禁止直接断电造成文件系统损坏；
- LCD和SD卡共用SPI时必须使用独立片选，并正确切换SPI配置；
- 为降低初期调试难度，优先考虑LCD使用SPI1、SD卡使用SPI2。

## 10. 中断规范

中断服务函数必须短小、不可阻塞：

- 不调用 `DelayMs()`；
- 不写SD卡文件；
- 不执行DHT20完整测量流程；
- 不进行LCD刷屏；
- 不执行格式化输出；
- 不分配动态内存；
- 只读取必要数据、更新计数、设置事件标志并清除中断标志。

中断和主循环共享的简单标志使用 `volatile`：

```c
static volatile bool timer_tick_pending;
```

`volatile` 不能保证多字节访问的原子性。共享多字节数据时，应使用短临界区
或安全的数据交换方式。

## 11. 延时与时间

- 时间变量名称带单位，如 `_us`、`_ms`、`_s`；
- `DelayMs()` 只用于基础实验中的简单演示和上电等待；
- 中断中禁止使用阻塞延时；
- 串口、I²C、SPI、ADC和SD卡轮询都必须设置超时；
- 使用无符号时间差处理系统计数回绕。

```c
const uint32_t current_ms = SystemTimeGetMs();
if ((current_ms - previous_ms) >= kTaskPeriodMs) {
  previous_ms = current_ms;
  ExperimentUpdate();
}
```

## 12. 内存与指针

- 当前阶段不使用动态内存分配；
- 优先使用静态缓冲区和固定容量数组；
- 指针使用前检查是否为 `NULL`；
- 数组和缓冲区访问必须检查长度；
- 输入数据不修改时使用指向 `const` 的指针；
- 不返回局部变量地址；
- 字符串处理必须预留结束符空间。

```c
bool BufferCopy(uint8_t *destination,
                uint16_t destination_size,
                const uint8_t *source,
                uint16_t source_size) {
  if (destination == NULL || source == NULL) {
    return false;
  }
  if (source_size > destination_size) {
    return false;
  }

  memcpy(destination, source, source_size);
  return true;
}
```

## 14. 错误处理

- 可恢复错误通过返回值报告；
- 多种错误使用枚举，禁止使用含义不明确的 `-1`、`-2`；
- 错误发生后外设应尽量恢复到明确状态；
- I²C总线忙、SPI超时、串口溢出和SD卡异常必须有退出路径；
- 示例程序应通过串口或LED给出可观察的错误提示。

## 17. 实验代码模板

```c
#include "experiment_adc.h"

#include <stdint.h>

#include "bsp_adc.h"
#include "bsp_usart.h"
#include "system_time.h"

static const uint32_t kPrintPeriodMs = 500U;

void ExperimentAdcInitialize(void) {
  AdcInitialize();
  UsartInitialize(115200UL);
}

void ExperimentAdcRun(void) {
  static uint32_t previous_print_ms;
  const uint32_t current_ms = SystemTimeGetMs();

  if ((current_ms - previous_print_ms) < kPrintPeriodMs) {
    return;
  }
  previous_print_ms = current_ms;

  const uint16_t adc_value = AdcReadRaw(0U);
  const uint32_t voltage_mv = AdcConvertToMillivolts(adc_value);
  UsartPrintAdcValue(adc_value, voltage_mv);
}
```

该模板体现了BSP与实验层分离、变量单位明确、非阻塞周期执行和统一命名。
