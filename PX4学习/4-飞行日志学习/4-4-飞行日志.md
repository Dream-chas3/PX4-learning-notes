# 飞行日志：uORB 发布订阅 + pthread 双线程架构

## 概述

本代码实现了一个完整的 **PX4 应用模板**：在一个独立的 PX4 任务中创建两个 pthread 子线程，一个以 1Hz 频率发布自定义 uORB 消息，另一个订阅并打印。这是 PX4 中最经典的用户态应用架构——**ModuleBase 任务框架 + pthread 并发 + uORB 通信**。

## 整体架构

```
test_app start
    │
    ▼
┌─────────────────────────────────────────────────────┐
│  PX4 Task "test_app" (run_trampoline → run)         │
│                                                     │
│  主线程:                    while(!should_exit())    │
│                                px4_sleep(1)          │
│                                                     │
│  ┌────────────────────┐  ┌────────────────────┐     │
│  │ thread_loop_send   │  │ thread_loop_receive│     │
│  │                    │  │                    │     │
│  │ orb_advertise      │  │ orb_subscribe      │     │
│  │   ↓                │  │   ↓               │     │
│  │ orb_publish(1Hz) ──┼──┼→ uORB 总线 ──→ orb_check │
│  │                    │  │   ↓               │     │
│  │                    │  │ orb_copy + 打印    │     │
│  └────────────────────┘  └────────────────────┘     │
│                                                     │
│  退出时: thread_should_exit=true → pthread_join     │
└─────────────────────────────────────────────────────┘
```

**层次关系**：
```
Nuttx Task (px4_task_spawn_cmd)
  └── run_trampoline (ModuleBase 蹦床)
        └── run()
              ├── 主线程: 等待退出信号
              ├── pthread_send: 发布 uORB
              └── pthread_receive: 订阅 uORB
```

## 一、uORB 消息定义：test_topic.msg

```c
uint64 timestamp          # 时间戳（微秒）
uint64 data               # 计数器值，发送线程每次递增
uint8 TEST_CONST_DATA = 0 # 常量字段（不可修改，通常用于枚举/标识）
# TOPICS test_topic test_topic_x  ← 关键：创建第二个 topic 实例
```

### `# TOPICS` 语法

```
格式: # TOPICS 主题名1 主题名2 主题名3 ...
```

编译后生成：
- `struct test_topic_s` — 消息结构体
- `ORB_ID(test_topic)` — 主题1的元数据
- `ORB_ID(test_topic_x)` — 主题2的元数据（本代码使用的就是这个）

> 这样做的好处：测试时用 `test_topic_x`，不影响真实系统中 `test_topic` 的数据流。

生成的 C 结构体：
```cpp
struct test_topic_s {
    uint64_t timestamp;
    uint64_t data;
    uint8_t TEST_CONST_DATA;  // 编译期常量，值为 0
};
```

## 二、发送线程：thread_loop_send

```cpp
void *thread_loop_send(void *arg) {
    test_topic_s test_data = {};

    // ① 公告主题（只需一次）
    orb_advert_t test_pub = orb_advertise(ORB_ID(test_topic_x), &test_data);

    uint64_t cnt = 0;
    while (!thread_should_exit) {
        // ② 填充数据
        test_data.timestamp = hrt_absolute_time();  // 微秒级时间戳
        test_data.data = cnt;

        // ③ 发布
        orb_publish(ORB_ID(test_topic_x), test_pub, &test_data);

        ++cnt;
        px4_sleep(1);  // 1Hz = 每秒一条
    }
    return nullptr;
}
```

**执行节奏**：
```
t=0s: publish {timestamp=T0, data=0}
t=1s: publish {timestamp=T1, data=1}
t=2s: publish {timestamp=T2, data=2}
...
```

## 三、接收线程：thread_loop_receive

```cpp
void *thread_loop_receive(void *arg) {
    // ① 订阅主题（只需一次）
    int test_sub = orb_subscribe(ORB_ID(test_topic_x));

    bool updated;
    test_topic_s test_data = {};

    while (!thread_should_exit) {
        // ② 检查是否有新数据
        orb_check(test_sub, &updated);

        if (updated) {
            // ③ 拷贝最新数据
            orb_copy(ORB_ID(test_topic_x), test_sub, &test_data);

            // ④ 打印（时间戳除以 1,000,000 转为秒）
            PX4_INFO("uorb topic send time is %lu s",
                     test_data.timestamp / 1000000u);
            PX4_INFO("test data is cnt = %lu", test_data.data);
        }
        px4_sleep(1);
    }
    return nullptr;
}
```

### uORB C API 四步调用链

```
orb_advertise()      orb_subscribe()
       ↓                    ↓
   注册为发布者          注册为订阅者
       ↓                    ↓
 orb_publish()        orb_check()  ← 检查有没有新数据
       ↓                    ↓
    数据进入总线        orb_copy()   ← 拷贝到本地 buffer
```

| API | 作用 | 调用频率 |
|-----|------|---------|
| `orb_advertise(ORB_ID, &init_data)` | 公告 topic，获取发布句柄 | 仅一次 |
| `orb_publish(ORB_ID, handle, &data)` | 发布数据到总线 | 每次 |
| `orb_subscribe(ORB_ID)` | 订阅 topic，获取订阅句柄 | 仅一次 |
| `orb_check(handle, &updated)` | 非阻塞检查是否有新数据 | 每次 |
| `orb_copy(ORB_ID, handle, &buffer)` | 拷贝最新数据 | 有新数据时 |

## 四、主线程：run()

```cpp
void TestApp::run() {
    PX4_INFO("start!");

    // ===== 阶段1：配置线程属性 =====
    pthread_attr_t pth_attr;
    pthread_attr_init(&pth_attr);
    pthread_attr_setstacksize(&pth_attr, 64);   // 线程栈大小（64字节偏小，仅示例）

    struct sched_param param;
    pthread_attr_getschedparam(&pth_attr, &param);
    param.sched_priority = SCHED_PRIORITY_MIN + 5;
    pthread_attr_setschedparam(&pth_attr, &param);

    // ===== 阶段2：创建两个子线程 =====
    pthread_t pth_send, pth_receive;
    pthread_create(&pth_send,    &pth_attr, thread_loop_send,    nullptr);
    pthread_create(&pth_receive, &pth_attr, thread_loop_receive, nullptr);

    pthread_attr_destroy(&pth_attr);   // 线程已创建，属性可释放

    // ===== 阶段3：主线程等待退出信号 =====
    while (!should_exit()) {
        px4_sleep(1);  // 每秒检查一次
    }

    // ===== 阶段4：优雅关闭 =====
    thread_should_exit = true;               // ① 通知子线程退出
    pthread_join(pth_send, nullptr);          // ② 等待发送线程结束
    pthread_join(pth_receive, nullptr);       // ③ 等待接收线程结束
}
```

### 四个阶段的执行时序

```
时间 →

主线程:  创建线程  销毁属性  ─┬─ while(sleep) ───→ 通知退出 → join等待 → 结束
         (立刻返回)           │    [阻塞]        [退出信号]
                              │
pth_send:         开始执行 ──→ publish + sleep ───→  检测标志 → return nullptr
                  1s后        循环...             退出循环
                              │
pth_receive:      开始执行 ──→ check + print ────→  检测标志 → return nullptr
                  1s后        循环...             退出循环
```

**关键设计**：
- `pthread_create` 是**非阻塞**的，创建完立刻返回，线程在后台并发运行
- 主线程阻塞在 `while(!should_exit())`，等待 `test_app stop` 命令
- 停时先设 `thread_should_exit = true`，再 `pthread_join` 回收线程资源
- 如果不 `join`，线程退出后资源泄漏（类似僵尸进程）

## 五、框架代码

### 任务创建

```cpp
int TestApp::task_spawn(int argc, char *argv[]) {
    _task_id = px4_task_spawn_cmd(
        "test_app",                    // 任务名
        SCHED_DEFAULT,                 // 调度策略
        SCHED_PRIORITY_MIN + 5,        // 优先级
        1024,                          // 栈大小（字节）
        (px4_main_t)&run_trampoline,   // ← 蹦床函数
        (char *const *)argv
    );
    return (_task_id < 0) ? PX4_ERROR : 0;
}
```

### 实例化

```cpp
TestApp *TestApp::instantiate(int argc, char *argv[]) {
    TestApp *instance = new TestApp();
    return instance ? instance : nullptr;
}
```

### 命令入口

```cpp
int test_app_main(int argc, char *argv[]) {
    return TestApp::main(argc, argv);
    //            ↑
    //  ModuleBase 的 main() 自动解析 start/stop/status 子命令
    //  并调用 task_spawn → run_trampoline → instantiate → run
}
```

## 六、完整调用链路

```
终端: test_app start
    │
    ▼
test_app_main()
    │
    ▼
TestApp::main()             ← ModuleBase 提供，解析 "start"
    │
    ▼
start_command_base()        ← ModuleBase 提供，防重入检查
    │
    ▼
TestApp::task_spawn()       ← 你写的，创建 PX4 任务
    │
    ▼
run_trampoline()            ← ModuleBase 蹦床
    │
    ├── TestApp::instantiate()  →  new TestApp()
    ├── _object.store(object)
    ├── object->run()           →  TestApp::run() ← 你的业务逻辑
    └── exit_and_cleanup()
```

## 关键知识点总结

| 层次 | 关键概念 |
|------|---------|
| **PX4 任务** | `px4_task_spawn_cmd` + `run_trampoline` 蹦床 |
| **ModuleBase** | CRTP 模板，自动提供 `main()` / `start_command_base` / `stop_command` |
| **pthread** | `pthread_create`（非阻塞）, `pthread_join`（阻塞回收） |
| **uORB 发布** | `orb_advertise` → `orb_publish` |
| **uORB 订阅** | `orb_subscribe` → `orb_check` → `orb_copy` |
| **优雅关闭** | 设退出标志 → 等待线程结束 → 回收资源 |
| **`.msg` 文件** | 定义消息结构，`# TOPICS` 创建多实例 |
| **test_topic_x** | `# TOPICS` 语法创建的测试用 topic 实例 |

## 七、飞行日志文件获取与分析

### 7.1 日志文件位置

SITL 仿真产生的 `.ulg` 日志文件存放在编译输出目录中，具体路径取决于你的 PX4 源码位置。

**本机路径**（源码位于 `~/workspace/PX4-Autopilot`）：

```bash
# 日志目录（按日期分文件夹）
~/workspace/PX4-Autopilot/build/px4_sitl_default/rootfs/log/

# 查看今天的所有飞行日志
ls ~/workspace/PX4-Autopilot/build/px4_sitl_default/rootfs/log/$(date +%F)/

# 最新的一次就是最近时间的 .ulg 文件
```

```
目录结构示例：
build/px4_sitl_default/rootfs/log/
├── 2026-08-03/
│   └── 03_47_29.ulg
├── 2026-08-11/
│   ├── 01_28_26.ulg
│   ├── 01_54_00.ulg
│   ├── 02_03_43.ulg
│   ├── 08_05_22.ulg
│   ├── 08_10_19.ulg
│   └── 08_17_27.ulg    ← 最新的一次飞行
└── ...
```

> 如果源码目录不同（如教程默认 `~/PX4_1.14.3`），对应改为 `~/PX4_1.14.3/build/px4_sitl_default/rootfs/log/`。

### 7.2 其他获取方式

| 方式 | 说明 |
|------|------|
| **QGC 地面站** | Analyze Tools → Log Download → 选中 `.ulg` → Download |
| **ROS 日志目录** | MAVROS 也会缓存日志，位于 `~/.ros/log/` 下按日期存放 |
| **真实飞控** | 通过 USB 连接飞控，QGC 下载 SD 卡中的日志 |

### 7.3 上传到 PX4 官方日志分析平台

网址：**[https://logs.px4.io/](https://logs.px4.io/)**

#### 使用步骤

```
① 仿真飞行结束后，获取 .ulg 日志文件（7.1 / 7.2 的方法）
       │
       ▼
② 打开 https://logs.px4.io/
       │
       ▼
③ 点击 Upload 按钮，选择 .ulg 文件上传
       │
       ▼
④ 等待分析完成（几秒到几十秒）
       │
       ▼
⑤ 在左侧导航栏查看各维度图表
```

#### 关键分析图表

| 图表 | 英文名 | 分析什么 | 调参关注点 |
|------|--------|----------|-----------|
| **飞行器姿态** | Vehicle Attitude | Roll/Pitch/Yaw 的实际值 vs 期望值 | 跟踪误差、震荡幅度、超调量 |
| **本地位置** | Local Position | X/Y/Z 位置跟踪曲线 | 航点到达精度、位置超调 |
| **角速度** | Vehicle Rates | 三轴角速度 p/q/r | 角速度控制器的响应速度和震荡 |
| **执行器输出** | Actuator Controls | 各通道电机/舵机输出量 | 是否饱和（输出达到上限） |
| **电池状态** | Battery | 电压、电流随时间变化 | 电池压降是否异常 |
| **GPS 精度** | GPS Uncertainty | 定位误差估计 | GPS 信号质量 |

#### PID 调参实战用法

调 PID 的基本方法就是**对比两次飞行的日志**：

```
第一次飞行（默认参数）              第二次飞行（调整参数后）
     │                                    │
     ├── 下载日志_A.ulg                    ├── 下载日志_B.ulg
     │                                    │
     └──────► 都上传到 logs.px4.io ◄──────┘
                    │
                    ▼
          并排对比同一个图表的曲线变化
          
          例如：MC_ROLLRATE_P 从 0.15 → 0.2
          → 看 Vehicle Rates 中 Roll 的跟踪曲线是否更快
          → 看 Vehicle Attitude 中有没有出现震荡
```

| 调了哪个参数 | 主要看哪个图表 | 判断标准 |
|-------------|--------------|----------|
| `MC_ROLLRATE_P/I/D` | Vehicle Rates + Vehicle Attitude | 角速度响应快且不震荡 |
| `MPC_XY_VEL_P/I/D` | Local Position | 位置跟踪快且不过冲 |
| `MPC_Z_VEL_P/I/D` | Local Position（Z轴） | 高度响应快且不震荡 |

> 💡 PX4 官方日志分析平台是开源工具，源码在 [github.com/PX4/flight_review](https://github.com/PX4/flight_review)，也支持本地部署。
